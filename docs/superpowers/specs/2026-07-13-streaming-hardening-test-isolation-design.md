# 流式传输与测试隔离加固设计

## 背景

提交 `780cfe13bebfef230781506f41afde0355f788c3` 已补充 Markdown 多行 SSE 的前后端回归测试，但复查发现三项风险：完整后端测试可能复用开发 PostgreSQL 引擎、生产 Nginx 可能缓冲 SSE、前端测试没有证明内容回调发生在 `done` 事件之前。

## 目标

1. 所有 pytest 进程在应用模块导入前固定使用独立 SQLite 测试库，并在破坏性建表操作前设置安全门。
2. 生产 Nginx 的 `/api` 代理明确关闭响应缓冲，保证 SSE 内容尽快送达浏览器。
3. 前端回归测试使用可控流，验证 Markdown 原始换行在结束事件之前实时交付。

## 方案

### 测试数据库隔离

在 `backend/tests/conftest.py` 的最早加载阶段设置测试数据库和测试密钥环境变量，并清理配置缓存；pytest 会话启动时加载数据库引擎并断言后端类型为 SQLite。`test_auth.py` 的 `drop_all` 前再检查一次引擎类型，避免未来测试入口变化时误删非测试数据库。

相比在各测试文件分别设置环境变量，全局 `conftest.py` 能在测试收集导入应用模块之前生效，消除由收集顺序导致的配置缓存竞争。

### 关闭生产 SSE 缓冲

在现有 Nginx `location /api` 中加入 `proxy_buffering off;`。该改动直接覆盖生产容器使用的配置，不扩展到无关的缓存或超时策略。

### 验证真实增量时序

将前端 `streamApi` 测试改为可控 `ReadableStream`：先只写入包含 Markdown 空行的内容事件，等待并断言回调收到原始换行；随后才写入 `done` 并关闭流。这样，即使客户端错误地缓存到流结束才派发内容，测试也会失败。

## 验收标准

- 单独的数据库隔离测试先失败，修复后通过；完整 `pytest` 在单进程中完成且不连接 PostgreSQL。
- Nginx 配置测试先失败，加入关闭缓冲配置后通过。
- 前端增量时序测试、全部前端测试和生产构建通过。
- `git diff --check` 无格式错误，且不改动无关文件。
