# AI 助手流式 Markdown 换行保真设计

## 背景与根因

AI 模型已在流式增量中返回 Markdown 换行，但后端目前将整个增量直接插入单个 SSE `data:` 行：

```text
data: {chunk}

```

当 `chunk` 是 `第一段\n\n第二段` 时，实际传输内容中只有第一行带 `data:` 前缀。前端 `parseSseBlock` 会忽略没有 `data:` 前缀的行，因此流式阶段丢失换行及其后的同批文本。后端数据库保存的仍是原始完整内容，流结束后前端重新加载历史消息，才会突然显示正确分段。

## 目标

- 在 AI 助手仍处于 `streaming` 状态时，实时保留模型增量中的原始 Markdown 换行。
- 连续换行、空行和独立换行增量均能按原顺序到达前端。
- 流式阶段累积的内容与最终持久化内容一致。
- 不根据句号、字数或前端猜测额外创造段落。

## 非目标

- 不修改 AI 系统提示词或回答风格。
- 不调整 Markdown 样式、聊天气泡布局或自动滚动逻辑。
- 不将现有文本 SSE 协议扩展为 JSON 增量协议。

## 设计

### 后端 SSE 编码

在 `backend/app/routers/streams.py` 增加一个小型私有 SSE 编码函数。该函数将一个逻辑增量按 `\n` 分行，并为每个物理行（包括空行）添加 `data: ` 前缀，最后用一个空行结束该 SSE 事件。

例如，逻辑增量：

```text
第一段

第二段
```

编码为：

```text
data: 第一段
data:␠
data: 第二段

```

上例中 `␠` 仅用于可视化表示一个普通空格；实际线上内容是空的 `data: ` 行。

编码函数应用到 AI 助手的增量、完成和错误事件，并复用于同文件中的其他文本流，避免同一 SSE 编码错误继续出现。心跳注释 `:keepalive` 保持不变。

### 前端数据流

前端保持现有结构：

1. `parseSseBlock` 收集同一事件的所有 `data:` 行，以 `\n` 重组为原始增量。
2. `streamApi` 在收到该事件时立即调用 `onChunk`。
3. `assistant` store 立即将增量追加到当前消息。
4. Vue 重新执行 `renderMarkdown`，在消息尚未完成时就渲染已到达的段落。

前端已具备多 `data:` 行重组能力，因此生产代码不需新增客户端分段算法。

### 错误与持久化

- 保留当前的安全错误提示、`done` 事件和心跳机制。
- 保留当前的消息状态变化与数据库写入流程。
- SSE 编码只改变线上表示，不改变用于持久化的 `content`。
- 若流中断，仍按现有逻辑保存已生成内容。

## 测试策略

1. 先在后端流测试中增加回归用例：伪造 AI 连续输出普通文本、独立换行和含空行的多行增量，断言编码后的每一行都有 `data:` 前缀。该测试在修复前必须因换行未编码而失败。
2. 扩充现有前端 SSE 解析用例，确认中间空 `data:` 行能重组为两个换行。
3. 确认完成事件之前的回调内容已是 `第一段\n\n第二段`，而不是在重载历史消息后才恢复。
4. 运行后端相关测试与完整 `pytest`，再运行前端 `npm test` 和 `npm run build`。

## 验收标准

- AI 模型在任意增量中输出 `\n` 或 `\n\n` 时，对话面板在流式生成期间立即显示对应换行或分段。
- 流式阶段累积文本与后端最终保存文本一致。
- 模型未输出换行时，系统不主动插入段落。
- 单行增量、错误提示、完成事件和 SSE 心跳行为保持正常。
